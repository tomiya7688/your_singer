# 対象を絞って調査・再開する

リポジトリの[AGENTS.md](../../../AGENTS.md)を正本にし、コマンドはリポジトリ直下で実行します。

1. 今回の「目的・必要な確認先・完了条件」を短く定めます。継続時は[引き継ぎ](../../../dev-guidelines/handoff.md)の該当Issueの記録と現在のgit状態を照合します。
2. [作業別の確認先](../../../dev-guidelines/context-map.md)の該当行から、実装とテストを選びます。表は探索の入口であり、正しさの根拠は原典です。
3. `rg --files <対象ディレクトリ>`で候補を絞り、`rg -n '<シンボルやエラー文>' <対象パス>`で定義・呼出先・関連テストを探します。`artifacts/`、生成物、モデル、非公開素材を通常検索へ含めません。個別の検証に必要なら対象パスだけ指定します。
4. 該当する関数・呼出元・仕様の節・テストの期待結果を読みます。既読で未変更の同じ資料は繰り返し開かず、版や差分が変わった場合に該当部分を読み直します。
5. 変更箇所・入出力・確認方法が分かれば修正へ進みます。追加調査は未解決の疑問を明示し、その疑問に答える参照先だけへ広げます。
6. コマンドやログは終了コード・失敗工程・必要な前後行から確認します。全文ログや調査履歴は外部ファイルへの参照で残し、会話へ繰り返し貼りません。
7. 終了・担当交代時は、今回の結果・未確認・次の一手を[引き継ぎ](../../../dev-guidelines/handoff.md)へ記録します。

規約・手順の追加方法と出典は[保守方針](../../../dev-guidelines/context-maintenance.md)を参照します。指示を全件展開して読み込むことは、このskillの目的ではありません。
