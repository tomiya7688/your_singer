# 使用量を無駄にしない作業規則

品質・機能・必須の検証とレビューは減らさない。減らすのは、結果を変えない重複・待機・往復だけである。

## 守ること

1. **直すだけのことは聞かずに直す。** CIの整形・lint・テスト失敗など、直す以外に選択肢が無い件を「直しますか」と尋ねて判断待ちにしない。質問は、答えで作業内容が変わる製品上の選択に限る。
2. **通知に空で返信しない。** 同じ内容のhookエラー・進捗通知には返信しない。原因が環境側なら1回だけ報告し、繰り返さない。
3. **ポーリングしない。** CI待ちは、完了まで待つ1本のバックグラウンド処理で行い、途中経過を何度も確認しない。
4. **ツール呼び出しはまとめる。** 独立した確認は1メッセージで並列に実行する。同じ状態を繰り返し確認しない。
5. **整形は最初から通す。** 触ったMarkdown・JSON・YAMLは、pushの前に `npx prettier --write` を、Pythonは Ruff を適用する（[ワークフロー](workflow.md)）。
6. **主張の前に中身を読む。** 「無い」「重複している」は、ファイルを読んでから書く。誤った主張は手戻りで最も高くつく。
7. **広い読み取り・棚卸しは軽いサブエージェントに任せ、結論だけを受け取る。** 数回の呼び出しで済む作業には使わない。

## 確認を取らずに進める（オーナー指示）

「進めてよいか」「マージしてよいか」を尋ねて止まらない。CIが全て成功し、競合が無く、自己レビューに未解決の指摘が無ければ、[作業フロー](workflow.md)に従ってマージまで進める。対象には、他のエージェントが作ったPRも含む（オーナーが常時許可している）。止まるのは次の場合だけで、止まった理由はPRに書く。

- CI失敗・競合・未解決のレビュー指摘が残っている。
- 作成者がPR本文に未解決リスクを明記している。
- 署名・配布・リリースなど、[別の規則](../AGENTS.md)でオーナーの動作確認を待つと決めた作業。

## 繰り返す作業はテンプレート（スクリプト）にする

同じ手順を3回やったらスクリプトにし、次からはそれを呼ぶ。手順を毎回考え直し、毎回ツール呼び出しを重ねるのが最大の浪費である。

| 作業                                       | 使うもの                                                                                                                          |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 変更ファイルの整形・整形確認               | `pwsh tools/dev/format_changed.ps1 [-Check]`                                                                                      |
| 設計書の照合（リンク・決定記録・索引）     | `python tools/dev/check_docs.py`（`check.ps1` に含む）                                                                            |
| 到達不能コードの検査（Python・PowerShell） | `pwsh tools/dev/check_unreachable.ps1 [-SelfTest]`（`check.ps1` に含む。C# は警告エラー CS0162、条件による到達不能・JS は対象外） |
| CI完了待ち→マージ                          | `pwsh tools/dev/finish_pr.ps1 -Pr <番号>`（バックグラウンドで1回だけ実行）                                                        |
| 検証一式                                   | `pwsh tools/dev/check.ps1`                                                                                                        |

新しい繰り返しを見つけたら、このtableに足す。設計書に関わる変更は、実装前に[着手前チェック](implementation-ready.md)と[決定記録](../docs/design/decisions.md)・[パケット](../docs/design/README.md)で照合し、食い違いはIssueに書く。

## 毎回読む規則は削らない

使用量を減らすために、AGENTS.md の「必ず守るもの」、着手前チェック、レビュー・検証の規則を削ったり、読まずに済ませたりしない。減らすのは、同じ内容を繰り返し書く・読む重複と、結果を変えない待機だけである。規則が長くなったら、正本へのリンクに置き換えて短くし、内容は正本に残す。
