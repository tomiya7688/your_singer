# 作業開始からマージまで

共同作業の実行手順の正本です。[AGENTS.md](../AGENTS.md)から必要な工程を参照してください。コミット・PR・文書は日本語で書きます。

## 作業の流れ

<a id="start"></a>

### 1. 開始: 最新化してからブランチを切る

```powershell
pwsh tools/dev/start_work.ps1 -Issue <番号> -Name <短い英語名>
```

このスクリプトは、未コミットの変更がないことを確認し、`main` を `git pull --ff-only` で最新化してから `issue-<番号>-<名前>` ブランチを作ります。
既存ブランチで作業を再開する場合も、先に `git pull --ff-only` してください。upstreamが未設定なら、確認した継続元を明示してください。未コミット変更がある場合は、その所有者と対象を確認し、自動stash・reset・無関係な変更の一括stageは行いません。
他のエージェントの作業と衝突しないよう、着手前に対象issueのコメントとオープンPRを確認します。
他PRを土台にする場合は依存PR・基点commit・PRのbaseを記載し、今回のIssueの差分だけが見えるbaseへ向けます。依存PRが未統合なら、依存状態を解消してからマージします。

### 2. 実装

- 1ブランチ = 1issue。無関係な変更を混ぜません。
- 実装を変えたら、関連する `docs/` の説明、宣言コメント、テストも同じPRで更新します。
- `artifacts/`、生成物、秘密情報、利用者の元素材はコミットしません。

<a id="check"></a>

### 3. 終了: 検証してPRを作る

1. 実行前に[実行環境](execution.md)で一時領域を設定し、`pwsh tools/dev/check.ps1` を実行します。変更範囲に応じて `-SkipDotnet` などで絞ってよく、絞った場合はPRに明記します。
   文書だけの変更では `-SkipDotnet -SkipWorker` を使い、追加したリンク・参照先とskill形式を確認します。ログ全文は`artifacts/`へ保存し、終了コード・失敗箇所・ログの場所を報告します。
2. コミットは `feat(#番号): 日本語の要約` 形式にします(`fix` / `docs` / `test` / `refactor` も可)。
   stageするのは今回のIssueのファイルだけです。ステージ済み差分を確認してからコミットします。
3. push して、`.github/pull_request_template.md` に沿ったPRを作ります。タイトルはコミットと同じ形式にし、本文に `Closes #番号` を入れます。

<a id="review"></a>

### 4. CIと自己レビュー

- 対象PRの最新headに対するCI(`ビルド・回帰テスト`と変更対象の追加workflow)が全て成功するまで待ちます。失敗したら原因を直して再pushします。CIを飛ばす・無効化する・テストを弱めて通すことは禁止です。
- マージ前に、[`コーディング規約.md`](../コーディング規約.md) と [`レビュー基準.md`](./レビュー基準.md) に照らして自分のdiffをレビューし、結果をPRの本文またはコメントに残します。
  - 命名、宣言コメント(JSON-like Comment Outs)、関数50/80行・ファイル300/500行
  - 境界条件、失敗時の状態、削除・上書き・外部プロセス・パス結合の安全性
  - docsと実装の一致、テストの有無、未実行の検証の明示
- 作成者以外のエージェントや人がレビューした場合は、その指摘も全て解消します。

<a id="finish"></a>

### 5. マージ

次を全て満たす場合にマージします。

- CIが全て成功している
- 自己レビューで未解決の指摘がない
- `main` との競合がない(あれば `main` を取り込んで再度CIを通す)

```powershell
gh pr merge <PR番号> --squash --delete-branch
```

squashマージとし、マージ後に `main` へ戻って `git pull --ff-only` します。
CIが失敗している、または自己レビューで問題が残る場合はマージせず、PRに状況を書いて作業を引き継ぎます。
force push、`main` への直接push、他者のPRの無断マージはしません。

## 引き継ぎ

作業を途中で終える場合は、PR(またはissue)に「完了したこと・残り・確認済み/未確認」を書きます。
記録する項目とローカル作業の扱いは[引き継ぎ](handoff.md)に従います。次のエージェントは該当する記録を読んでから着手します。
