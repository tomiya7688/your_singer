# your_singer

ノイズを含む動画・音声素材から、対象話者の **歌唱モデル** と **トークモデル** を自動構築することを目指すプロジェクトです。

単一の綺麗な収録データセットを前提にせず、配信アーカイブ、動画、録音、音声ファイルなどのまとまった素材群から、音声抽出・分離・話者識別・区間分割・品質判定・学習用データ生成までを行い、既存の音声合成ソフトで利用できるモデルとして出力します。

> 現在は設計・仕様策定段階です。

## 目標

v1 では、次の一連の処理を一つのソフトで完結させることを目標とします。

```text
動画 / 音声素材
    ↓
音声抽出・前処理
    ↓
ノイズ / BGM / 他話者の分離
    ↓
話者検出・話者選択
    ↓
発話 / 歌唱区間の分類
    ↓
音素・F0・タイミング等の解析
    ↓
品質チェック・必要に応じた補完 / 補正
    ↓
共通内部データセット
    ├─→ 歌唱モデル
    └─→ トークモデル
```

## v1 の基本方針

- **歌唱モデルとトークモデルの両方を生成可能**にする
- 片方だけ、または両方を選択して生成できる
- 入力は単一ファイルにも対応するが、**フォルダ入力を主用途として設計**する
- フォルダ配下の対応メディアを再帰的に読み込む
- フォルダ全体を一つの素材ライブラリ / プロジェクトとして扱う
- 複数話者が検出された場合、ユーザーが学習対象話者を選択できる
- 同じ人物が複数クラスタに分かれた場合は話者クラスタを統合できる
- 誤検出された区間は個別に除外できる
- 複数の話者を選択し、それぞれ別モデルとして生成することも想定する
- 日本語の50音・音素カバレッジを学習前に診断する
- データ不足は原則として学習禁止条件にせず、品質上の注意として表示する
- 不足・不安定な発音や声質の **補完 / 補正機能をON/OFF可能**にする
- 補完 / 補正は **デフォルトON** とする
- ON時は欠損補完だけでなく、外れ値抑制、誤認識補正、特徴推定、条件間整合なども行う想定
- OFF時は、可能な限り観測された学習データを優先する
- 初期出力は独自形式よりも、**既存ソフトで読める一般的な形式への対応を優先**する
- 将来的には、スクリプトで声色や発声特性を時間変化させられる独自形式にも対応できる構造にする

## 初期出力候補

### 歌唱

第一候補として **OpenUtau / DiffSinger 系互換形式**を想定します。

### トーク

第一候補として **Style-Bert-VITS2 系互換形式**を想定します。

具体的な互換範囲、必要ファイル、学習方式は実装着手前に各プロジェクトの現行仕様を確認し、`docs/` 内の仕様として固定します。

## 入力

単一ファイルまたはフォルダを指定できます。UI上はフォルダ指定を主導線にします。

想定する代表的な入力形式:

- 動画: `mp4`, `mkv`, `webm`, `mov`, `avi`, `m4v`
- 音声: `wav`, `flac`, `mp3`, `m4a`, `ogg`, `opus`

実際のデコード可能範囲は FFmpeg 等のバックエンドに委ねる方針です。

## 話者選択

素材全体を横断して話者クラスタリングを行います。

```text
video01.mp4 → Speaker A / B
video02.mp4 → Speaker A / C
video03.mp4 → Speaker A

        ↓ 全体で統合

Speaker 01  91分
Speaker 02   7分
Speaker 03  16分
```

ユーザーは各話者を試聴して、モデル化する話者を選択できます。

## 50音・音素カバレッジ

ユーザー向けには「50音がどの程度揃っているか」を表示しますが、内部では単なる文字数ではなく、音素単位の出現量・文脈・発声条件も評価します。

例:

```text
50音カバレッジ: 43 / 46

不足:
ぬ / ぺ / ぽ

出現量が少ない:
ぎ / りょ / ふ

⚠ 一部の発音データが不足しています。
学習は続行できますが、該当する発音で品質が不安定になる可能性があります。
```

拗音、濁音、半濁音、促音、撥音、長音、外来語系の拡張音素なども別途評価対象にします。

歌唱モデルでは音素だけでなく、音域、母音伸長、高低音域での発声、子音→母音遷移なども品質診断に利用する予定です。

## 補完 / 補正

補完 / 補正機能はユーザーがON/OFFできます。**デフォルトはON**です。

### ON（推奨）

- 欠損音素の推定
- 少量データの補助
- 外れ値の抑制 / 破棄
- 誤ラベル・誤認識の補正
- 他の音や発声条件からの特徴推定
- 音素間・音域間・文脈間の特徴整合

単に「足りない音を人工的に作る」だけではありません。素材が汚い、偏っている、一部だけ発声が崩れている場合には、補正によって **ONの方が元話者の特徴に近づく可能性もあります**。

### OFF

推定による修正を最小限にし、観測された学習データを可能な限り優先します。十分に整った高品質な学習データがある場合や、素材に含まれる発声傾向を強く残したい場合に選択できます。

したがって、ON/OFFは単純な「高品質 / 低忠実度」「低品質 / 高忠実度」という関係ではありません。素材品質によって結果は変わります。

## 共通内部データセット

歌唱用・トーク用に前処理を完全二重化せず、一度解析した結果を共通中間形式に保存し、そこから各Exporter / Trainerへ渡します。

```text
project/
├─ sources/
├─ extracted/
├─ separated/
├─ cleaned/
├─ segments/
├─ rejected/
├─ metadata/
│  ├─ segments.jsonl
│  ├─ speakers.json
│  └─ styles.json
└─ features/
   ├─ phonemes/
   ├─ f0/
   ├─ energy/
   ├─ speaker/
   └─ style/
```

各セグメントには、元ファイル、話者ID、文字起こし、音素、F0、品質スコア、speech / singing分類などを保持します。

## 再解析の最小化

フォルダ前提のため、同じ素材ライブラリにファイルが追加された場合に全件を解析し直さない設計を目指します。

ファイルごとに次のような情報を保持します。

- path
- size
- modified time
- content hash
- analysis version

変更・追加されたファイルだけ再解析し、既存解析結果を再利用できるようにします。

## 将来構想

v1では既存形式への出力を優先しますが、内部はExporterを差し替え可能にします。

```text
exporters/
├─ diffsinger/
├─ style_bert_vits2/
└─ custom/
```

将来の独自形式では、モデル本体だけでなくランタイム制御とスクリプト層を持たせ、例えば以下のような声色変化を扱えることを想定しています。

```text
0.0s  voice = normal
2.4s  timbre = soft
4.0s  breathiness = 0.7
6.2s  formant = +0.15
8.0s  style = whisper
```

この独自形式は将来機能であり、v1の必須範囲には含めません。
