# 音素補完候補の生成・検証・採用（実験実装）

## 対応と前提

Issue #9の未録音音素補完への追補。#15で保存・通信・学習入力の回帰を検証する。
今回接続するのは、対象話者の学習済みStyle-Bert-VITS2 2.7.0モデルを使い、未観測音素または観測3回未満の少量音素を含む文章を会話音声として合成する経路である。
元波形にある短いF0欠損の補間とは別処理。モデル未学習の話者を参照録音だけで合成するゼロショット機能ではない。
まず観測データで学習したモデル、または同じ話者の既存モデルが必要になる。モデル未準備なら保留し、別人の既定モデルを代用しない。
生成モデルが未観測の音素を正しく生成できることや、追加学習で品質が向上することは保証しない。

## 操作

「4. 学習・書き出し」の「音素補完候補（実験）」を開く。
対象話者の明瞭な観測会話区間、生成モデルのフォルダ、モデル内の話者名、生成する日本語文章を指定する。
参照は2～14秒のPCM16モノラル音声とし、手動除外した区間は候補にしない。
文章の音素列に、その話者で0〜2回しか観測されていない補助対象音素がある場合だけ生成する。0回は「未観測」、1〜2回は「少量」として区別する。文章は改行なし120文字以内。

生成終了後に機械検証結果を表示する。試聴して発音・話者を確認し、チェックを付けて「採用」を押した場合だけ学習入力に追加する。
検証不合格の候補は採用不可。候補ファイルは原因確認用に保持する。
初期実装では話者ごとに一つの文章を採用でき、別候補の採用は置き換えとなる。採用解除もできる。
大量の合成データ追加や合成データからの再帰的な補完は行わない。

## 生成と検証

1. Style-Bert-VITS2の `TTSModel.infer` を指定した `speaker_id` で実行する。スタイルはNeutral、CPU、乱数シード0。
2. 48 kHz・PCM16モノラルWAVを生成する。振幅の自動正規化で音割れを隠さない。
3. faster-whisperで生成音声を再認識し、pyopenjtalkで読みへ変換する。
4. 指定文の音素列と再認識文の音素列を照合する。
5. SpeechBrainのECAPA話者特徴を参照音声と生成音声から再抽出し、余弦類似度を計算する。
6. 長さ、実効振幅、音割れ率、20ミリ秒窓による無音率を検証する。

初期採用基準は話者余弦類似度0.80以上、認識区間の最小平均対数確率-0.50以上、最大無音発話確率0.20以下、音声長2～14秒、実効振幅0.008以上、音割れ率0.001以下、無音窓率0.60以下。
これらは未校正の設計閾値で、本人である確率や発音の正解確率ではない。
音素列の照合はASRと読み変換を利用した代理検証であり、音素の音響的な直接認識や強制アラインメントではない。ASRによる誤った整合、話者検証の誤判定を排除できないため、試聴確認を残す。

## 保存と学習入力

```text
features/phoneme-supplements/<候補ID>/
├─ candidate.wav
└─ candidate.json
metadata/phoneme-supplements.json  # 話者ごとの採用候補ID
```

候補に生成モデルの場所と話者名、モデル一式の内容指紋、生成器版、参照区間、参照音声と生成音声のSHA-256、観測メタデータの指紋、指定文章、再認識文章、検証音素列、補助対象音素、各対象音素の元観測回数、未観測音素一覧、品質指標、採否理由を保存する。
生成・検証中にモデルや参照音声・観測メタデータが変われば失敗させる。
途中で失敗した候補ディレクトリは公開せず除去する。元録音・元UVD・既存学習結果は変更しない。

`AutoCorrectionService` は新たな生成を実行せず、保存された採用候補だけを読み取る。
ON時だけ会話区間として学習用の投影に追加し、OFF時は参照しない。歌唱データには混ぜない。
生成区間IDは `generated_<候補ID>`、source_idは `generated:<候補ID>` とし、補正記録はestimated/appliedとする。
音素時刻・元観測のASR信頼度・F0特徴を捏造しないため、生成会話の該当項目は未設定のままとする。トーク前処理が検証された本文から音素・アクセントを生成する。
観測UVDやカバレッジ集計には生成区間を保存しない。生成データの採用で録音済み音素の回数を増やさない。未観測と少量の警告は「生成で録音済みになった」とは扱わない。

採用時と学習用投影の読み取り時の両方で、観測指紋、参照音声、生成音声のハッシュを再確認する。
古い候補は勝手に流用せず、再生成または採用解除を要求する。候補採用・解除で学習データ指紋も変わり、ジョブは再作成が必要となる。
補正処理版はv1-08.6。旧ジョブは既存の履歴・再作成画面から作り直す。generator v1の未観測音素候補は互換読み込みを維持し、v2から少量音素と元観測回数を追加する。

## 同梱リソース（開発・配布側の準備）

生成用の話者モデルは `config.json`、`style_vectors.npy`、使用する `.safetensors` 1件を持つフォルダを指定する。
補助モデルはアプリの次の場所へ実ファイルとして配置する。

```text
workers/models/phoneme-supplement/
├─ japanese-bert/  # ku-nlp/deberta-v2-large-japanese-char-wwmのローカル一式
├─ asr/            # faster-whisperが読める日本語対応CTranslate2モデル一式
└─ speaker/        # speechbrain/spkrec-ecapa-voxceleb、hyperparams.yamlと全重み
```

日本語発音辞書もワーカーへ含める。開発環境ではworkerの `phoneme-supplement` optional dependencyを使う。
これは配布物を作る側の手順であり、利用者にPythonやpipの導入を要求する方針への変更ではない。
モデルが未配置なら失敗し、空の成功応答・無音・他話者モデルで代用しない。
Hugging Face/Transformersのオフライン指定と、ASRのlocal_files_only、SpeechBrainのallow_network=Falseを利用する。
モデル一式の配布、依存関係を含む実ワーカーのパッケージ化、ライセンス・利用条件の同梱確認は未完了。信頼できないモデル設定、独自コードを含むモデルパッケージを読み込ませない。

## 通信

生成器の依存をコマンド選択後に読み込み、依存不足をJSON応答に変換する。
Pythonのライブラリログは標準エラーへ分離する。
C#は両パイプを並列に読み、要求ID・終了コード・応答サイズを検証し、中断時にプロセスツリーを停止する。
ログは末尾64 KiB、JSON応答は4 Mi文字に制限する。ネイティブライブラリが標準出力へ直接書く場合はJSON不正として失敗し、成功扱いにしない。

## 少量音素の補助

信頼できる観測会話（ASR / alignment confidence 0.65以上）の音素を話者単位で数える。
対象カタログ内で観測回数が3回未満の音素を補助対象とする。

- 0回: missing-phoneme-generation / estimated
- 1〜2回: sparse-phoneme-generation / weak_observed
- 3回以上: 自動生成補助の対象外

候補文章に含まれる補助対象だけをcandidateのtarget_phonemesへ保存する。
生成音声を採用しても観測回数は変えず、CorrectionRecordのoriginal_valueへ元の0〜2回を保存する。
これにより「録音が増えた」のではなく「生成データを補助的に追加した」ことを追跡できる。

文字起こし自動補正と同時に使う場合、不足・少量判定は補正後の学習用音素列で再計算する。
一方、保存済み生成候補の出自・参照音声・観測回数の再検証は自動補正前の観測UVD＋手動編集を基準にする。
自動補正が投影を変えただけで既存候補が無効化されないよう、2つの境界を分離する。
