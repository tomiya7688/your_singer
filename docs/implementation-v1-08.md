# v1-08 実装設計: 自動補完・補正

## 対象と現在の範囲

Issue #9 の追補。回帰テストは #15 に対応する。

現時点で実際に学習入力へ適用する処理は、低信頼区間の自動除外と、元音声で裏付けられる短い音高特徴の欠損補完である。
未録音の音素を話者らしい音声として生成する処理、音素ラベルの自動再認識、広い音域・発声条件への変換は未実装。
対象を記録しただけの処理を補完成功とは表示しない。

## ON/OFF

`AutoCorrectionSettings.Enabled` は既定でON。`PitchCompletion.Enabled` は音高補完だけの個別設定で既定ON。
OFFでは補完ファイルを生成せず、元の音高・有声性を使う。手動の除外、話者統合、分類修正はON/OFFに関係なく有効。
元の録音、抽出音声、共通音声データの保存ファイル、観測特徴を上書きしない。

## 状態と適用状況

`state` は observed / weak_observed / estimated / corrected / rejected を保持する。
`application_status` を追加し、実施状況を区別する。

| 適用状況 | 意味 |
| --- | --- |
| unknown | 適用情報がない旧記録。実施済みと推測しない |
| not_required | 元の観測値・判定根拠の記録 |
| applied | 値の補完、補正、または学習入力からの除外を実施した |
| deferred | 条件不足、未実装などにより未適用 |

旧API名 `AppliedCorrections` は互換性のため残すが、中には保留記録も含まれる。利用側は必ず適用状況を見る。
同じ音素を `original_value` と `corrected_value` に書くだけで「補正済み」にしていた処理は廃止する。
欠損音素は話者単位で集計し、他人の音素が存在することをその話者の充足と扱わない。

## 短い音高欠損の補完

`PitchGapInterpolator` と `PitchFeatureCompletionService` を `src/process/YourSinger.Process/processing/dataset/completion/` に置く。
C#で完結し、この処理のためにPythonや追加のMLモデルを必要としない。

対象は歌唱区間の時刻付きF0、音量、有声性のJSON配列。これは `universal_features.py` が保存する既存形式である。
0 Hzの未検出フレーム、または信頼度0.45未満の正のF0を候補にする。信頼できる正のF0は変更しない。

採用条件は次の通り。

- 欠損時間は既定60ミリ秒以下。先頭・末尾からの外挿をしない。
- 両端とその一つ外側に60～1200 Hzの観測があり、信頼度が既定0.8以上。
- 前後の有声性と音量が十分である。
- 両端の差は既定2半音以下。外側の観測との変化も1半音以内。
- 同じ一つの母音 a / i / u / e / o の時刻範囲内で、音素信頼度が既定0.65以上。子音・無声化母音・音素境界を跨がない。
- 欠損区間の特徴音量に大きな低下がない。
- 元のPCM16モノラルWAVでも欠損フレーム自体の実効振幅が既定0.008以上である。
- 候補F0の周期に対応する遅れで元音声の正規化相関が既定0.9以上。解析窓は40ミリ秒または3周期の長い方。

一つの欠損区間の全フレームが条件を満たす場合のみ、対数周波数上の線形補間を採用する。
例えば一定の220 Hzが続く実波形で特徴が `[220, 0, 0, 220]` と抜けている場合、条件を満たせば `[220, 220, 220, 220]` になる。
これは特徴の補完であって、音声の穴を録音らしく作り直す処理ではない。

閾値は保守的な初期設計値で、実素材で校正された値ではない。相関を正解確率と呼ばない。
補完フレームの信頼スコアは最大0.65とし、元の集約 `PitchReliability` を水増ししない。
F0平均・標準偏差、有声フレーム率、音高幅は補完後の特徴に合わせて学習用の投影で更新する。

### 重要な制約

現在の音素時刻抽出には文章を等分割する近似が残っており、実アラインメントではない。
そのため音素範囲の一致だけで正しい発音区間だと保証せず、元波形の確認を併用する。
周期性のある伴奏などの誤判定も完全には排除できない。実素材での補完精度と学習品質は別途検証する。

## 保存・出自・キャッシュ

```text
features/completion/short-vowel-gap-1/<入力指紋>/
├─ f0.json
├─ voicing.json
└─ manifest.json
```

入力指紋は元波形と3種類の特徴ファイルのSHA-256、区間・話者・音素情報、補完設定、アルゴリズム版を含む。
元の特徴ファイル内容だけが変更された場合も補完ONの入力指紋は変わる。

一時ディレクトリで全ファイルを完成させてから公開する。既存キャッシュは期待内容との一致を検証して再利用し、破損したものを学習に渡さない。
処理中に元音声や特徴の内容が変わった場合は失敗させる。失敗時の一時ディレクトリを除去する。
後続の別区間が失敗した場合、先行して完成したキャッシュは残ることがあるが、元データも保存済みの補正設定も書き換えない。

`metadata/auto-correction.json` に、話者、区間、開始フレーム、終了フレーム（終端を含まない）、変更前後の数値列、入力指紋、元と補完後の特徴パス、手法、スコア、採用／保留理由を保存する。
時刻はフレーム列の `time_sec` と対応付ける。

## 学習入力への接続

既存の `TrainingDatasetSnapshotService` が手動編集を投影し、`AutoCorrectionService` が補完を実施する。
歌唱ジョブの作成と `DiffSingerDatasetBuilder` の入力解決は同じ処理を通るため、ONでは実際に補完後のF0ファイルを参照する。
OFFでは元ファイルへ戻る。素材の再抽出・分離・文字起こしは行わない。

設定と適用記録を指紋へ含める。元波形、特徴、補完設定がジョブ作成後に変われば、古いジョブは再作成を要求する。
指紋方式を更新するため、旧学習ジョブも再作成が必要。
この接続は歌唱学習データの構築までであり、実Trainerの完走やOpenUtau互換性を意味しない。
トーク用の未録音音素生成は、この音高補完では解決しない。

## テスト

`PitchCompletionTests` で、数値補間、元波形の周期性確認、ON/OFF、歌唱データへの実値反映、無音・雑音・子音・長い欠損・音高段差の保留、原本不変、キャッシュ破損拒否、設定・内容変更時の無効化、キャンセル、手動除外維持を確認する。
音声は既知の正弦波・無音・雑音を生成して使う。実話者認識や音素生成モデルのテストではない。
既存の回帰テストも同時に実行する。

## 未録音音素の補完に残る仕事

話者条件付きの音声／音響特徴生成器を接続し、要求した音素が実際に出現すること、話者特徴、生成音声の品質を検証してから学習入力へ採用する必要がある。
音素ラベルだけの捏造、別音素の貼り替え、他人の録音の自動混入、モデルのない空の成功応答は行わない。
自動補完全体、誤ラベル再認識、広域の条件間補間をこの追補だけで完了扱いにしない。
