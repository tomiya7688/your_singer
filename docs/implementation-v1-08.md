# v1-08 実装設計: 自動補完・補正

## 対象と現在の範囲

Issue #9。回帰検証は #15。

学習入力へ適用する処理は、低信頼区間の自動除外、元音声で確認できる短い音高欠損の補完、および利用者が明示採用した生成会話候補の追加である。
生成会話候補は対象話者の既存Style-Bert-VITS2モデルが必要な実験経路で、詳細は `docs/phoneme-supplements.md` を参照する。実モデルの推論完走・補完精度・学習品質は未検証。
未学習話者のゼロショット生成、音素ラベルの自動再認識、歌唱の広い音域・発声条件への変換は未実装。
対象を記録しただけの処理や、生成候補を保存しただけの状態を補完成功とは扱わない。

## ON/OFF

`AutoCorrectionSettings.Enabled` は既定ON。`PitchCompletion.Enabled` は音高補完だけの個別設定で既定ON。
OFFでは補完ファイルを生成せず、元の音高・有声性を使い、採用済みの生成会話も追加しない。
手動除外、話者統合、分類修正はON/OFFに関係なく有効。元録音、抽出音声、保存済み共通音声データ、観測特徴は上書きしない。
生成会話は機械検証だけでなく、別画面での試聴確認と採用操作を必要とする。ジョブ計画のたびにモデルを起動して生成し直すことはしない。

## 状態と適用状況

`state` は observed / weak_observed / estimated / corrected / rejected を保持する。
`application_status` は unknown（適用情報がない旧記録）、not_required（観測の記録）、applied（実施済み）、deferred（保留）を区別する。
旧API名 `AppliedCorrections` は互換性のため残すが、保留記録も含むため利用側は適用状況を見る。
音素名を変更前後に同じ値で保存しただけの処理を「補正済み」としない。
未観測音素は話者単位で集計し、他人の観測や生成音声の採用でその話者の録音済み音素を増やさない。

## 短い音高欠損の補完

`PitchGapInterpolator` と `PitchFeatureCompletionService` を `src/process/YourSinger.Process/processing/dataset/completion/` に置く。
この処理はC#で完結し、Pythonや追加MLモデルを必要としない。
入力は歌唱区間の時刻付きF0・音量・有声性のJSON配列で、`universal_features.py` の形式を使う。
0 Hzまたは信頼度0.45未満の正のF0を候補にする。信頼できる正のF0は変更しない。

採用条件:

- 欠損は既定60ミリ秒以下。先頭・末尾から外挿しない。
- 両端とその一つ外側に60～1200 Hz、信頼度0.8以上の観測がある。
- 前後の有声性と音量が十分で、両端差2半音以下、外側との変化1半音以内。
- 同じ母音 a / i / u / e / o の範囲内で音素信頼度0.65以上。子音・無声化母音・音素境界を跨がない。
- 欠損区間の特徴音量に大きな低下がない。
- 元PCM16モノラルWAVの該当フレームの実効振幅0.008以上。
- 候補F0周期で元音声の正規化相関0.9以上。解析窓は40ミリ秒または3周期の長い方。

一つの欠損区間の全フレームが条件を満たす場合のみ対数周波数上で線形補間する。
一定の220 Hzが続く元波形で特徴が `[220, 0, 0, 220]` なら、条件通過時に `[220, 220, 220, 220]` へ補完する。
これは特徴の補完であり、録音自体の穴を合成するものではない。
補完フレームの信頼スコアは最大0.65で、集約PitchReliabilityを水増ししない。
F0平均・標準偏差、有声率、音高幅は学習用の投影で更新する。

### 制約

閾値は未校正の初期設計値であり、相関を正解確率と呼ばない。
現在の音素時刻抽出には等分割の近似が残るため、音素範囲の一致だけで採用せず元波形を併用する。
周期的な伴奏などの誤判定を完全には排除できない。実素材の精度と学習品質は別途検証する。

## 音高補完の保存とキャッシュ

```text
features/completion/short-vowel-gap-1/<入力指紋>/
├─ f0.json
├─ voicing.json
└─ manifest.json
```

入力指紋に元波形、3種類の特徴のSHA-256、区間・話者・音素情報、補完設定、アルゴリズム版を含める。
一時ディレクトリで完成させてから公開し、再利用時は内容を検証する。
元音声・特徴が途中で変われば失敗し、途中の一時ディレクトリを除去する。
後続区間の失敗時に先行して完成したキャッシュは残る場合があるが、元データと保存済み設定は書き換えない。

`metadata/auto-correction.json` に、話者、区間、開始・終了フレーム（終端を含まない）、変更前後の値、入力指紋、元と補完後のパス、手法、スコア、採用・保留理由を保存する。

## 学習入力への接続

`TrainingDatasetSnapshotService` が手動編集を投影し、`AutoCorrectionService` が音高補完と採用済み生成会話の追加を行う。
歌唱のDataset BuilderはON時に補完後F0を参照する。生成会話はトークのDataset Builderだけへ渡し、歌唱と混ぜない。
生成会話に音素時刻・F0・観測信頼度を捏造して付けない。生成物の出自は候補記録と生成専用区間IDで保持する。
観測の再抽出・分離・文字起こしは行わない。
設定・適用記録・生成区間を入力指紋へ含める。設定・入力や候補採用が変われば古いジョブは再作成を要求する。
補正処理版はv1-08.4。旧ジョブの移行は `docs/training-job-recreation.md` を参照する。

## 検証と残件

`PitchCompletionTests` は既知の正弦波・無音・雑音を使い、実値補間、条件不足の保留、原本不変、キャッシュ破損拒否、設定・内容変更、キャンセル、手動除外の維持を検証する。
`PhonemeSupplementTests` とPython候補検証テストは、差し替えたモデル応答で候補隔離・採用・OFF・原本不変・古い候補拒否を検証する。これを実話者の音素生成成功や学習品質改善の証明としない。
実Trainerの完走、外部ソフトでの推論、初回モデルがない話者の補完、誤ラベル再認識、歌唱条件付き生成は未完了。

## 文字起こしの自動再確認（v1-08.5）

低信頼の文字起こしを即座に別文字列へ置き換えない。
自動補正ON時に限り、ASR信頼度0.35以上0.65未満かつalignment confidence 0.35以上の観測会話・歌唱区間を再確認する。
0.35未満の区間は従来どおり外れ値として除外し、この再確認で救済しない。

同梱ASRを次の2条件で再実行する。

- beam size 5
- beam size 1

両結果をpyopenjtalkで音素化し、音素列が完全一致した場合だけ補正候補とする。
さらに次をすべて満たす必要がある。

- 2方式のうち低い方の再認識信頼度が0.72以上
- 観測ASR confidenceから0.12以上改善
- 正規化後の文字起こしが元観測と異なる
- 候補文字列・音素列・音声長が有効

条件を満たした場合、学習用投影の `Transcript`、`Phonemes`、`AsrConfidence`、`AlignmentConfidence` だけを更新する。
観測UVDは保存し直さない。
補正OFFにすると観測値へ戻る。

CorrectionRecordには次を保存する。

- state: corrected または weak_observed
- method: transcript-consensus-1
- application_status: applied または deferred
- original_value
- corrected_value
- confidence
- 採用・保留理由

手動transcript overrideがある区間は対象外とし、利用者の編集を自動補正で上書きしない。
同梱workerまたはASRモデルがない場合も処理全体を失敗させず、deferredとして観測値を保持する。
worker自体の破損や不正応答など、単なる未配置ではない異常は成功扱いにせずエラーとする。

この方式は2つの独立した認識モデルによる多数決ではなく、同じローカルASRのdecode条件違いによる整合確認である。
そのため自動補正が常に正しいことを意味しない。実素材での誤訂正率・改善率の評価は#15の実測対象とする。


## 他音素からの話者特徴推定（v1-08.7）

採用済み生成会話には、生成器が出した音声から直接抽出した値を「観測済みSpeakerEmbedding」として保存しない。
同じ話者の信頼できる観測区間から、補助対象音素以外を含む区間だけを参照し、話者特徴を推定する。

`SpeakerFeatureEstimator` は次を満たす観測区間を使う。

- 同一話者
- source_id が `generated:` ではない
- ASR / alignment confidence が0.65以上
- SpeakerEmbeddingが存在し有限値
- confidence 0.65以上の音素に、今回の補助対象以外の音素が少なくとも1つある

参照特徴の次元が一致する場合だけ平均し、L2正規化して生成区間の学習用 `SpeakerEmbedding` へ設定する。
CorrectionRecordには `estimated / applied`、method `cross-phoneme-speaker-feature-estimation`、推定ベクトル、候補生成時の話者類似度をconfidenceとして保存する。

対象音素しか含まない観測しかない、特徴がない、次元が不一致、不正値、平均ノルムが0の場合は `estimated / deferred` とし、空のSpeakerEmbeddingを維持する。
生成区間は推定元から除外するため、生成データを使って次の生成データの話者特徴を再帰的に補強しない。

この値は本人性を保証する埋め込みではなく、既存の話者クラスタで保持している特徴を「別音素の観測から引き継いだ推定値」と明示するための構造である。
現在のStyle-Bert-VITS2/DiffSinger Dataset Builderがこの埋め込みを直接学習条件として消費するわけではない。
将来の共通モデル・独自Exporterが利用できる中間特徴として保持する。
