# 精度評価・回帰防止・本番採用ゲート

## 目標

**正確そうに見える指標を増やすことではなく、現実の使用条件で正しい話者・発音・音程・声質を得ること**。

評価は「個々の解析段階」＋「最終モデルの使い勝手」の両方で行う。ある段階の指標だけ良くても、出力モデルの話者類似度・発音・音質・処理時間が悪化すれば、既定モデルや既定ルートへ採用しない。

## 1. 三段階の評価素材

| 種別                | 内容                                                                                                     | 測れること                                       | 限界                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------- |
| A. 合成混合         | 既知のクリーン会話/歌唱とBGM/雑音/残響を人工的に混ぜる。元音声・タイムスタンプ・話者が既知               | SDR等、音素・F0・分離の正解との差                | 本物の配信素材の劣化を完全には再現しない       |
| B. 注釈付き現実素材 | 配信、ライブ、会話、歌唱、BGM混入などの実動画/音声の一部へ人手で話者・発音・歌詞・区間・音高の正解を付与 | 現実ドメインでのCER/DER/F0等                     | 全録音のクリーン音声や正確なF0がない場合がある |
| C. モデル生成テスト | 学習に使用しない文章と歌詞+音符、数話者、会話/歌唱の混在と音域を準備                                     | 実際に使えるモデルか、声質・発音・音程・音声劣化 | 客観指標のみでは主観的品質は確定できない       |

これらは**テストfixtureの公開と、非公開の実音声データの持ち出しを混同しない**。公開できる合成素材と権利状態が明らかな非公開素材を分けて管理し、音声ファイルをリポジトリへ無断追加しない。

## 2. 評価対象を層別にする

評価ベースラインを少なくとも次の条件で区切る。

- 素材: 綺麗な会話 / 雑談 / ライブ歌唱 / 伴奏の強い歌唱 / MC＋歌唱混在 / 合唱・話者重複
- 声: 男女・声域幅 / 囁き・息声 / 高音裏声 / ラップ・早口 / 音量の大小
- 撮影収録: 圧縮音声 / 高残響 / 強いBGM / 雑音 / クリッピング / 複数マイク
- データ量: 十分 / 少量 / 少ないが希少な音素・音域を含む
- 失敗: 無音、破損、過度に短い区間、話者不明、歌詞不明、モデル未導入・VRAM不足

極端に簡単な素材だけを合格にして、雑多な素材への改善を主張しない。サンプル数は用途ごとの分布が判別できる規模にし、難条件が少ない場合は `insufficient_evidence` を明示する。

## 3. 評価指標と正解が必要な条件

| 領域           | 指標・表示                                                                                               | 判定上の注意                                                                      |
| -------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| VAD/話者       | 音声区間miss/false alarm、DER/JER、重複話者の取り扱い、target speakerの誤混入率                          | 誤話者を学習へ混入することは、少量データでも大きな損害。cos類似度は正解率ではない |
| Speech/Singing | speech/singing/ambiguousのconfusion matrix、macro F1、誤った教師データへの投入割合                       | ambiguousを無理に片方へ割り当ててF1を操作しない。abstain率も報告                  |
| ASR/歌詞       | 正解付きCER/WER、歌詞の読み・音素誤り率、認識断念率                                                      | Whisper logprobやモデル間一致は正解率でない                                       |
| 音素境界       | 人手修正した音素境界との差の中央値・90%点、順序/時間異常率                                               | 有効なMFA出力は境界の形式的妥当性であり正確さとは別                               |
| F0/有声        | raw pitch accuracy、gross pitch error、オクターブ誤差率、voicing precision/recall、信頼できるF0 coverage | 正解F0がない素材でF0 RMSEを捏造しない。比較時のframe rate/timebaseを一致          |
| 音声候補       | 正解clean vocalがある場合SDR/SIR/SAR等、声質保持・音素欠損・残BGM・artifactの主観/客観評価               | true referenceのない録音の`separated/raw RMS`をSDRや残BGM比とは呼ばない           |
| 生成トーク     | 未学習文章のCER、話者類似度、合成失敗率、聴取評価（明瞭度/声質/自然さ）                                  | ASRと生成モデルの誤りは独立でない場合がある。必ず試聴も確保                       |
| 生成歌唱       | ノートF0追従、音符/音素欠落、声質類似度、アーティファクト、OpenUtauの実レンダリング                      | ピッチ指標だけ良くても声質やビブラートが消えていたら改善としない                  |
| 処理コスト     | 実行時間、peak VRAM、disk/cache増加、失敗率                                                              | 高品質プロファイルと軽量プロファイルを別に評価                                    |

上記の定義・算出ライブラリ・バージョン・collar/重複区間の扱いは評価configとして固定する。DER・JER等の定義は `pyannote.metrics` などの実装に合わせる（https://pyannote.github.io/pyannote-metrics/reference.html）。RMVPE方式の比較には論文を参照（https://arxiv.org/abs/2306.15412）。

## 4. 信頼度の校正

対象: speaker similarity、歌唱/会話のscore、ASR confidence、alignment confidence、F0/voicing confidence、分離音声の採用評価。

- `raw_score`、`score_kind`、`model_revision`、`calibration_status`、`calibration_dataset_id` を保存する。
- 未校正のモデルscoreを `probability` と呼ばない。clamp済みcosineも0〜1の範囲であるだけで確率ではない。
- 校正用ラベルがある場合、正解と予測スコアを集めてreliability diagram、Brier/ECE等で評価する。少数サンプルのECEだけで安全だと決めない。
- 歌唱と発話、BGM有無、codecが異なるとスコアの意味が変わり得るため、評価層別にcalibration gapを記録する。
- `calibrated` は対象モデル・対象ドメイン・校正データID・校正方式の組合せであり、別モデルへ自動転用しない。
- 非校正でも用途別のrelative rankを使える場合はあるが、`70%正しい` のUI表示は禁止。
- `#63` の未校正MFA confidence 0は0%正確を意味しない。評価側でもunknownに分離する。

現場の誤りリスクの例: 雑音下のWhisperが誤りへ過剰な確信を示す研究（https://doi.org/10.1109/ASRU65441.2025.11434626）、収録条件・codec差でspeaker embedding性能が劣化する検証（https://www.isca-archive.org/interspeech_2025/ferrofilho25_interspeech.html）。

## 5. データ分割とリーク防止

- **素材源・録音session・同一動画・同一曲/同一フレーズ/重複clipをgroupで束ねて分割**する。10秒クリップをランダムにtrain/testへ振ってはならない。
- 同一話者の声質評価は学習内外の発話/歌唱条件が違うことも検証。
- 校正データ、policy tuningデータ、最終holdoutテストを区別する。holdoutを見ながら閾値調整しない。
- 重み計算で頻度や品質分布を学習集合以外から参照しない。最終評価側の希少音素をtraining utilityに使わない。
- 同じ音声のraw/sep/denoised派生を別サンプルとして学習/valにまたがって配置しない。
- checksumだけではエンコード違いや前処理違いの近似重複を検出できない。音声fingerprint・時間帯・source lineageでも照合する。

## 6. 精度改善の採用ゲート

### ベースライン

現行single-path Demucs/heuristic classifier/自己相関F0/単一Whisperを再実行可能な **Baseline v1** として固定し、model revision、配置済み資源、実素材集合、seed、プロファイルを記録する。baselineが重大エラーで完走できない場合も失敗率として保存する。

### 候補を採用する条件

1. 変更したstage自体の指標で、十分な正解付き素材に対し有効な改善があること。
2. 対象話者の誤混入、誤歌詞の教師化、オクターブ誤判定、元音の消失等の**重大退行が増えない**こと。
3. 最終のトーク/歌唱合成の発音・声質・音程/音質・利用可能率が同程度以上であり、特定条件で悪化した場合は理由とデフォルト切替条件を説明できること。
4. 軽量/標準/高品質のVRAM・時間・CPU fallbackが、製品の実行上限に収まるか、制約をUIに明示できること。
5. モデル本体とcheckpointのライセンス、同梱サイズ、オフライン動作が配布要件を満たすこと。
6. 検証結果を測定数、信頼区間またはばらつき、困難条件の個別ケース、使用したテストセットrevisionとともに記録すること。

**合格の数値は未検証の現段階では捏造しない**。ベースラインと正解付きデータを固定し、誤りの実害を見て採用閾値を事前登録する。差が僅か・nが少ない・トークだけ改善して歌唱劣化が大きい場合は `inconclusive` とする。

### モデル選択ルール

- 1つの特徴・素材で最良のモデルが別特徴でも最良とは限らない。
- `confidence` だけでなく誤話者・誤歌詞・声の劣化などの重大リスクを優先。
- 不確実な場合は早期にraw/既存モデルへ戻せること。比較不能な候補を優れた新モデルとして既定化しない。
- フラグ/モデルprofileで新旧ルートを差し替え、以前のcacheと結果を消さない。
- 選択結果のprovenanceとexclusion/weighting情報を `Universal Voice Dataset`→training jobへ渡す。

## 7. 自動CIと実機確認

- 合成fixture CI: timebase、manifest、variantの欠損/破損、モデル不一致、理由コード、score status、OVERRIDE優先、降格可能性。
- 固定小規模正解付きテスト（権利的に公開できる場合のみCIに同梱）: F0 octaves、CER、話者重複、分類の誤振り分け等。
- 実GPUローカル: ソース分離→識別→特徴抽出→2学習方式→本物の歌声/話し声の試聴。
- 配布: 同梱モデルの資源hash、ライセンス、VRAM、YourSinger.exe単一起動、不要な初回ネット取得がないこと。
- 失敗した場合は**失敗原因を記録し、結果だけ良い部分を選んで公表しない**。

## 8. v1とv2

v1: 初期の複数候補の比較、重要区間での相互検証、用途別入力候補選択、音高・話者・歌詞信頼度の来歴管理、品質ゲート。

v2: Source Profileと大量の運用評価結果によりモデル選択・学習レシピ・weightをさらに自動最適化する。**v1で複数モデル協調をやらない理由にはしない。**
