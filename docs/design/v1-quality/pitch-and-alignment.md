# F0・有声性・歌詞/音素タイミングの高信頼抽出

## 対象と目的

`audio_features.py` は40ms窓・10ms hopの自己相関F0、`universal_features.py` はFaster-WhisperとMFA経路で音素時刻を作る。これらを破壊せず、**歌唱で問題となるオクターブ誤差・BGM混入・息声・ビブラート・母音伸長・歌詞不一致**に対する頑健な抽出を追加する。

v1の狙いは「複数手法の結果を実際に比べて正しい音高・タイミングを得る」ことであり、RMVPE等の単なるバックアップ実装ではない。

## 1. F0候補の作り方

- 既存の自己相関F0をbaselineとして保持する。
- 第2系統の歌唱向けモデルとして **RMVPE系** を優先評価する。RMVPEは伴奏付き多声音楽から直接F0を推定する構成を扱っており、音声分離の結果に依存しない候補を作れる（論文: https://arxiv.org/abs/2306.15412）。
- 軽量環境ではモデルサイズ・入力条件・ライセンスと速度を評価し、別の歌唱F0モデル/信号処理器へ差し替え可能にする。
- **原音に対するRMVPE系** と **分離音声に対する自己相関/ML推定**を照合可能にする。分離失敗時もF0抽出を試みる価値がある。
- すべて同じ `canonical_sample_time` に合わせ、frame時刻を同期。フレーム間隔は各モデルに違いがあっても結果の値を無根拠に平滑化しない。

## 2. 提案するFrameF0Hypothesis

```json
{
  "segment_id": "seg_12",
  "timebase": {"sample_rate": 44100, "origin_sample": 0},
  "hypotheses": [
    {
      "id": "pitch-poly-1",
      "input_audio_candidate_id": "raw-0",
      "model_id": "rmvpe-compatible",
      "model_revision": "locked-sha",
      "frames": [
        {"time_samples": 22050, "f0_hz": 440.0, "voiced_score": 0.91, "score_kind": "model_voicing_score"}
      ]
    },
    {
      "id": "pitch-sep-1",
      "input_audio_candidate_id": "sep-A",
      "model_id": "autocorr-v1",
      "frames": [
        {"time_samples": 22050, "f0_hz": 220.0, "voiced_score": 0.82, "score_kind": "periodicity"}
      ]
    }
  ],
  "disagreement": [{"time_samples": 22050, "type": "octave_difference"}],
  "selected_hypothesis_id": null,
  "selection_status": "unresolved"
}
```

`voiced_score` の数値は校正済み確率ではない（モデル由来のscore_kindを持つ）。exampleの数値を合格閾値にしない。F0=0は「無声音」を意味する場合と「モデル失敗/未計測」を分け、未計測時は `null` とstatusを保存する。

## 3. 比較アルゴリズム

1. 無声/有声の候補マスクを作る。フレーム時刻誤差・サンプリング差は明示的に整列する。
2. F0候補ごとに、有限値・範囲内・過度な跳躍・不自然な短時間反転・オクターブ差・欠損の指標を抽出する。
3. 同じ区間の複数F0が1octave前後だけ違うケースは `octave_ambiguous` と記録。単純な平均 `(220+440)/2=330Hz` にしてはならない。
4. ピッチの連続性だけで正解と判断しない。ビブラート、音程跳躍、裏声、グリッサンド等の本物の歌唱表現を失わない。
5. 音楽信号や他話者のF0の取り込みは、音源候補・voicing・話者混入度など別証拠と照合する。
6. 候補スコアと時間領域で選択した範囲を保存し、未解決は `needs_review` として残す。優秀な候補があるからといって全曲に同じモデルを一律適用しない。
7. 長い欠損部のF0は自動創作しない。既存補完ONでは隣接する信頼可能部分に制限して補完し、`estimated` とprovenanceを付ける。

### 選択の実装案

F0の最適経路は **短い時間範囲単位で動的に選択できる**。ただし時刻を跨いで別モデルのframe列を切り貼りする際は、不連続が発生した境界を検査し、`source_hypothesis_id` を各区間に持たせる。無制限の自動合成はしない。候補間のどちらが正しいか判断できないケースは原候補を保持し、下流で重み・確認待ち扱いとする。

## 4. Forced alignment と文字起こしの信頼性を分ける

- 現行MFAの出力するphone列が正規化結果と一致しても、歌詞が正しいとは証明されない。
- **「MFAで計算された境界」≠ 正確な実測のグラウンドトゥルース**。文書では原則「MFA推定境界」「音素列検証済み境界」と書き、未校正の0 confidenceを0%正解扱いしない。
- 歌詞/テキストの候補が複数ある場合、候補ごとに辞書・音素列・align実行結果を保存し、モデル間で境界の安定性・音響の整合を評価する。
- 境界だけ一致、音素列だけ一致などを別statusで管理する。時刻単調性、正の持続長、音声範囲内の時刻は**形式的妥当性**であり、実際の音との一致精度の証明ではない。
- 促音、撥音、長母音、無声化母音、息、AP/SP（無音/息）等は、固定辞書との対応と正規化履歴を保全する。未知ラベルを無言で最寄り音素に置換しない。
- manual lyric overrideを入力した場合、旧MFA境界を再利用せず、該当区間だけ再phonemize / alignする。
- alignmentが使えない区間も声質特徴抽出などの別用途では保持し、使用目的別のeligibilityを設定する。

## 5. 歌唱への学習入力

`DiffSingerDatasetBuilder` に渡すのは、出所・時刻が明確な音素とF0/有声列。

- acoustic trainingのF0は、選択したframe seriesと元音声時刻の対応hashを保存して再現できるようにする。
- duration trainingは、歌詞と境界が十分に検証された区間だけ使い、そうでない区間を音響/声質などの別用途へ回す。
- 短い音高補完では元F0/補完F0の両方を保持し、歌唱の自然な揺れを消し過ぎない。
- 1音符しかない場合など、音符列の正解を元素材から勝手に捏造しない。ノート情報の推定と音声F0観測を別に保存する。
- speakerの声質学習用に使えるか、pitch/phoneme/durationの教師データに使えるかは異なるので、用途別適格性/weightの入力へ渡す。

## 6. 実装順・テスト

1. 既存の自己相関Series、MFA参照、新モデル候補のrecord構造とtimebaseを定義。
2. 信頼度status/候補保存を実装。
3. 第2F0 extractorを実装し、raw/sepの違う音声に対して比較。
4. オクターブ差・有声不一致・境界不正を検出し、採否理由を保存。
5. MFA歌詞整合/整列の比較を追加する。
6. 実歌唱に近い正解付き合成と非公開手動注釈素材でRPA、GPE、voicing precision/recall、音素境界MAE（正解がある範囲のみ）を検証。
7. 実OpenUtau歌声のF0/発音への効果を確認し、退行する場合は旧候補へ戻せるようにする。

テストする失敗: 220Hzと440Hz、零音声、裏声、低音域、音域跳躍、BGM強いフレーズ、残響、話者の重なり、語尾伸長、無声化母音、促音、前処理による音声時間ずれ。誤差しきい値は `quality-gates.md` の手動正解付き評価から決める。
