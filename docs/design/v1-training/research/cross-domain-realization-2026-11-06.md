# 調査報告: トーク・歌唱の声質の相互利用を実現する経路（2026-11-06）

調査担当: Codex gpt-6-luna（公開資料のウェブ調査）。依頼文は固定版のコード読取の事実（DiffSinger は話者ID表のみ、SBV2 は話者ID表とスタイルベクトル）を含み、「できるか」ではなく「実現できる具体的な経路」を求めた。以下は Luna の報告で、設計の根拠として使うが、各項目の「確認できた事実」の出典は実装前に再確認する。

以下は公開資料で確認できた実装・研究例です。ライセンスはコードと重みで条件が異なる場合があるため、配布前に対象バージョンの個別ライセンスを確認してください。

## 1. DiffSinger に話し声の声質を使う経路

**確認できた事実**

- DiffSinger の複数話者学習は、複数データセットをまとめ、`speakers`・`spk_ids`・`use_spk_id` で話者IDを扱う仕組みです。複数話者モデルでは話者を選ぶほか、話者間の声質やスタイルを混ぜられると説明されています。[設定仕様](https://github.com/Metal-Studioo/OpenVpi-DiffSinger/blob/main/docs/ConfigurationSchemas.md)・[Best Practices](https://github.com/Metal-Studioo/DiffSinger-openvpi/blob/main/docs/BestPractices.md)
- これは学習済み話者IDの混合であり、外部話者埋め込みを直接入力する機能ではありません。ユーザー確認済みの OpenVPI v2.5.1 の仕様とも整合します。
- 話し声のみから歌唱を作る研究例として Learn2Sing があり、歌唱教師コーパスと対象話者の通常発話を共有話者埋め込みで学習し、対象話者の歌唱を合成したと報告しています。[論文](https://arxiv.org/abs/2011.08467)・[プロジェクトページ](https://welkinyang.github.io/learn2sing/)
- OpenUtau は DiffSinger をサポートします。Windows では標準はCPU描画で、任意に DirectML を利用できます。[OpenUtau案内](https://github.com/openutau/openutau.com/blob/main/wiki/DiffSinger-support.md)

**推測・未確認**

- Learn2Sing の方式を DiffSinger に移植するには、話し声と歌声に共通の話者表現を学ぶ訓練経路が必要です。設定だけで実現できる根拠は見つかりませんでした。話し声を歌声用データとしてそのまま追加するのも、音素・音高・持続音の教師信号が異なるため同等の方法とは言えません。
- `spk_mix` の利用可否・仕様は、今回確認できた OpenVPI の資料では明確に確認できませんでした。少なくとも、既知の話者ID混合は外部埋め込み注入とは別機能です。

## 2. 話し声が多く歌声が少ない場合

**確認できた事実**

- Learn2Sing は、歌唱データが対象話者になくても、歌唱教師と対象話者の発話から対象話者の歌唱を作る研究例です。[論文](https://arxiv.org/abs/2011.08467)
- 声質変換を後段に使う候補として RVC があります。公式説明では少量データ学習（目安10分以上）や高音域のピッチ抽出への対応を掲げ、コードは MIT です。[RVC README](https://github.com/0lav/RVC/blob/main/docs/en/README.en.md)・[ライセンス](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/LICENSE)

**推測・未確認**

- DiffSinger の話者ID表を拡張して話者別の歌声を学習する方が、出力形式を維持しやすい一方、歌唱が少ない話者では過学習や音域・母音の不足が残りえます。歌声変換を組み合わせる場合も、歌唱のピッチ、長い母音、ビブラートを保てるかは話者・音域ごとの評価が必要です。これらを特定データ量で保証する公開実例は確認できませんでした。

## 3. 歌声が多く話し声が少ない場合

**確認できた事実**

- Style-Bert-VITS2 は AGPL-3.0 で、学習時の各音声に対応するスタイルベクトルと、推論時の参照音声からのスタイルベクトル生成に対応しています。[README・ライセンス](https://github.com/sync-dev-org/Style-Bert-VITS2)・[推論仕様](https://github.com/sync-dev-org/Style-Bert-VITS2/blob/master/docs/spec/core-inference.md)
- 参照音声からスタイルを得られることは、歌声を入力できることや、歌声から話者固有の声質だけを分離できることの証明ではありません。
- ゼロショット日本語TTS候補 Irodori-TTS は参照音声による話者クローンに対応し、リポジトリに Windows/CUDA 12.8 の導入手順があります。コードは MIT、重みはモデルカードの条件確認が必要です。[公式リポジトリ](https://github.com/Aratako/Irodori-TTS)
- Qwen3-TTS は Apache-2.0 のコード・モデルとして公開され、日本語を含む多言語と短い参照音声からのクローンを掲げています。公式評価表にも日本語の音声内容・話者類似度が掲載されています。[公式リポジトリ](https://github.com/QwenLM/Qwen3-TTS)

**推測・未確認**

- Style-Bert-VITS2 では歌声からスタイルベクトルを作る実装上の入口はありますが、歌唱入力で安定した日本語発話になるか、歌唱由来のピッチ・伸ばし・残響が話し声へ混入するかは未確認です。参照音声の切り出し・複数ベクトル平均を試す価値はありますが、品質改善は保証できません。
- Irodori-TTS／Qwen3-TTS は歌声参照の適合性や、得られた声を再配布可能な話者モデルとして保存する条件を別途検証する必要があります。ゼロショット推論が、そのまま再学習可能な声庫を作るわけではありません。

## 4. 実現経路候補（実現しやすい順）

| 順  | 経路と作業                                                                                                                                 | 素材量・主な限界                                                                                                       |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 1   | **話し声→TTS**：既存 Style-Bert-VITS2 の話者学習＋参照音声スタイル生成。形式維持には小規模なデータ前処理・推論統合。                       | まず話し声を優先。歌声参照での品質は要評価。AGPL-3.0 の派生・配布条件に注意。                                          |
| 2   | **歌声→トーク**：Irodori-TTS または Qwen3-TTS に歌声を参照として渡す。パッチ不要の推論経路。                                               | 短いクリーンな歌声から試せるが、発話再現性・声の一貫性は未確認。出力はトークTTSであり SBV2 形式ではない。              |
| 3   | **話し声→歌唱**：話し声と歌唱教師を使う Learn2Sing 型の話者共有学習を実装し、推論・エクスポート層を DiffSinger/OpenUtau に接続。           | 対象話者の歌声なしでも研究上の実例あり。DiffSinger移植はモデル・学習パイプラインの大規模改修。教師歌唱コーパスが必要。 |
| 4   | **歌唱変換併用**：話し声を歌唱生成し、RVCで対象声へ変換して歌唱コーパスを増強、DiffSingerを学習。                                          | 公式案内のRVC目安は対象話者10分以上。変換音声を教師に使うため、ピッチ・母音・音域の誤差が学習結果に入る懸念。          |
| 5   | **DiffSinger話者拡張**：複数話者IDで歌唱を学び、話者混合を使う。外部話者埋め込みを使うなら埋め込み抽出器・投影層・学習処理のパッチが必要。 | 話し声だけでの声質学習を実現する既成設定は確認できず、単純なID追加だけでは解決しない。                                 |

**実装判断としては**、話し声中心の話者には現行SBV2、歌声中心にはまず参照音声型TTSを試し、OpenUtau互換の歌唱が必須なら Learn2Sing 型の研究実装か、歌唱変換で歌声素材を補う方向が候補です。特に「話し声だけから DiffSinger 声庫」は、既存設定ではなく研究方式の移植を要するものとして見積もるのが妥当です。
