# 質感プリセット分類と現行音声合成方式の対応（v1）

## 前提：プリセットは「製品名」でも「単なるモデル選択」でもない

Your Singerのユーザーは **生成目的（トーク／歌唱／両方）** と **目指す質感** を別々に選ぶ。

- 「古いボカロのような電子的な声」は意図された表現であり、「低品質」の意味ではない。
- 「複雑な声」は多様な抑揚・発声・息・強弱・音色変化などを保つ **高表現・多次元的な声** の希望として扱う。
- 素材に大量の歌唱があっても、トークモデルの「クラシックな電子的音声」を指定できる。
- 実装方式の名前と質感の名前は別。あるモデルが必ず特定の質感になると保証しない。
- 特定の商用製品のエンジン・音声DB・本人の声をそのまま複製することは要件ではない。**表現上の特性を明示し、対応する技術で実現する**。

## 1. 2026年11月時点の代表方式と学習上の特徴

| 系統 | 技術・製品の例 | 音声表現の特徴と設計に取り込む点 | Your Singerへの位置づけ |
|---|---|---|---|
| 従来型の歌声合成・サンプル／パラメータ制御 | 初期VOCALOID系、UTAU系、従来の音声結合・リサンプリング方式 | 固定的なピッチ、輪郭が明確な音素接続、比較的機械的な音色も表現の個性となる | 「クラシック電子的」プリセットの**質感参照**。特定商用エンジン互換の実装ではない |
| 現代型の音符制御歌声合成 | DiffSinger / OpenUtau、Synthesizer V Studio 2 | 音高曲線、音素長、tension、breathiness、energyなど複数の制御軸。学習可能な制御軸は声庫／モデルの仕様に依存 | v1標準歌唱はDiffSinger系。商用ソフトは設計参照であって、同梱可能な学習Backendを意味しない |
| スタイル条件付き音声合成 | Style-Bert-VITS2 | 発話スタイル・強弱・感情に関わる条件を制御できる構成 | v1の既存トーク出力。新しい声質プリセットに必要な表現能力を固定版で検査 |
| Zero-shot・指示条件付き表現豊かなTTS | CosyVoice 3、Qwen3-TTS | 参照音声、声質設計、自然言語でのスタイル指示など多様な声の制御方式 | トークの将来・追加Backend候補。コード・重みのライセンス、オフライン同梱、学習/出力互換を別々に確認 |
| Voice Conversion・話者適応 | RVC/類似の声質変換系 | 既存音声の音色を対象話者へ適応するが、文章/音符から直接生成する能力とは区別が必要 | 片側素材から別目的モデルを作る際の補助候補。最終出力形式のTrainerが必要なら別に用意 |

これは製品の性能ランキングではない。各モデルの「ユーザーに聞こえる質感」は学習データ・話者・実装・合成パラメータで変化する。

## 2. v1のプリセット分類案

「モデル名の羅列」ではなく、**出力先targetを跨いだ意味のある分類**にする。プリセットIDは安定させ、ユーザー表示名は日本語にする。

| preset_id（案） | 日本語表示 | 主な目標特徴 | 主用途 |
|---|---|---|---|
| `classic_synthetic` | クラシックな電子的音声 | 制御されたF0輪郭、比較的規則的なタイミング、意図的に合成感を残した音色 | 歌唱/トーク |
| `clean_controlled` | 明瞭・制御重視 | 明瞭な発音、安定した音程/抑揚、ノイズの少なさ | 歌唱/トーク |
| `natural` | 自然な声 | 声色の忠実性、自然な微細変動、違和感の少ない遷移 | 歌唱/トーク |
| `expressive_complex` | 高表現・複雑な声 | 高い表現幅、細かな強弱/音色変化、発声の多様性 | 歌唱/トーク |
| `soft_breathy` | 柔らかい・息混じり | 小さい緊張感、息成分、優しい発声 | 歌唱/トーク |
| `powerful` | 張りのある力強い声 | 張り、声の芯、強弱変化、高音域の表現 | 歌唱/トーク |
| `characterized` | 個性的・キャラクター寄り | 収録声質の特徴を優先し、独特な話し方/歌い方を残す | 歌唱/トーク |
| `reference_match` | 参考音声に近づける | ユーザーが選んだ同一話者の参考区間と質感を優先 | 歌唱/トーク |

v1での**初期候補**であり、すべてを同時に「実装済み」と表示してはならない。Backend/Exporterで実現・検証できないものは `unsupported` または `preview`。プリセットは今後追加・変更できる。

### プリセットは独立軸も持つ

- `syntheticness`（電子的↔自然）
- `expressiveness`（安定↔表現豊か）
- `breathiness`（クリア↔息成分）
- `tension`（柔らかい↔張りがある）
- `articulation`（滑らか↔明瞭）
- `texture_reference`（どの同一話者音声を目指すか）

これらは**内部の目標軸**であり、数値をそのまま全Backendへ渡す共通APIではない。制御可能な部分だけをBackend Adapterが変換する。相関した指標や実装固有のパラメータを、他実装の同名パラメータと無検証で同一視しない。

## 3. 目標質感を作るための学習/合成工程

質感を「学習時だけで作る」と決めつけず、次を明示的に組み合わせられるようにする。

1. **素材選択**: どの参考発声やstyleを用いるか。目的別教師データと話者の声質参照を分離する。
2. **モデル構造/Backend**: 対象targetと質感軸に対応するモデル/Trainer/Exporterを選ぶ。
3. **学習レシピ**: 条件付き学習、style balancing、適格性・品質weighting、補完/補正、学習段階、scratch/fine-tune等を選ぶ。
4. **合成時設定**: サポートされるならF0変動、breathiness、tension、phoneme timing、prosody等を設定・同梱する。
5. **検証**: 話者本人らしさ、発音、音程、音響の破綻、**目標質感への適合**を評価。自動指標だけで質感を完全判定したと主張しない。

たとえばクラシック電子的な質感は、モデルをわざと過学習・低性能にするのではなく、**声色を維持しながら表現の規則性・音色・合成制御を選択する**。高表現はF0の微細変動やbreathiness、多彩なstyleをすべて保つことを検討するが、無根拠に別人らしい声へ寄せない。

## 4. プリセットの宣言形式（Modユーザーでも追加可）

```json
{
  "schema_version": "1",
  "id": "example.voice.classic",
  "version": "1.0.0",
  "display_name_ja": "クラシックな電子的音声",
  "targets": ["singing", "talk"],
  "desired_traits": {
    "syntheticness": 0.85,
    "expressiveness": 0.25,
    "articulation": 0.85
  },
  "preferred_strategy_tags": ["controlled_pitch", "structured_timing"],
  "fallback_strategy_tags": ["timbre_preservation"],
  "description_ja": "規則的な発声と電子的な質感を目標にするプリセット"
}
```

**ModユーザーはJSONでプリセットを作れる**。必要な制御軸やタグに対応した学習戦略が登録されていない場合は、希望の表示だけして「実現済み」と誤認させない。パラメータ名・意味・推奨範囲はversion付き辞書で検証する。

## 5. 品質評価の原則

- 話者忠実性とプリセット適合度は別評価。「電子的」を選んだ結果の自然度の低さだけで不合格にしない。
- クラシック系でも歌詞・音素・音程の正確さは必要。人工的な質感は壊れた音声・音割れと区別する。
- `natural` や `expressive_complex` は本人らしさ・発話/歌唱能力を失わない範囲で実現する。
- 同一素材・同一targetで異なるプリセットを比較するときは、実際の出力WAV/モデル成果物に差があることを検証。プリセット名だけが変わる実装は禁止。
- ユーザーの選んだpreset ID/version/参照区間を学習Jobと生成モデルメタデータに保存する。
