# 設計の決定記録

実装パケットで見つかった、Issue同士・Issueと設計正本の食い違いへの対応です。実装前に「要決定」が残らないよう、ここで状態を決めます。変更するときは、このファイルを直すPRを出し、影響するIssueを列挙してください。

## 状態の意味

| 状態   | 意味                                                                                                     |
| ------ | -------------------------------------------------------------------------------------------------------- |
| 確定   | 依存の書き漏れ・用語の不一致など、機械的に整理できるもの。この内容で実装してよい                         |
| 暫定   | 製品としての選択を含む案。オーナーが確定するまでこの案で進めてよいが、確定時に変わりうることをPRに書く   |
| 待ち   | 未マージの設計PRが正本になる項目。マージ後に突き合わせる。それまで、その領域の実装には着手しない         |
| 実装内 | 数値・名前など、実装Issueの担当がPRで根拠つきの初期値を提案し、オーナーが承認する。versionつきで保存する |

## パケットの要決定の扱い

各パケットの「要決定」のうち、この記録にID付きで載せたものは、そこに書いた状態に従います。載せていない項目は、数値・名前・閾値・画面の細部であり、状態は一律「実装内」です。実装Issueの担当が、PRで初期値と根拠を提案し、オーナーが承認するまでは「暫定」として扱います（D-00）。

## 一般則

- **D-00 数値と閾値**: 閾値・許容誤差・件数の下限は、設定とversionで保持する。初期値は、実測（#117のBaselineや実素材）か出典で決め、PRに根拠を書く。根拠がない間は、測定して保存しても合否判定には使わず、状態を `unavailable` とする。測れていない指標を満点や合格にしない。（確定）
