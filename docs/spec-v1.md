# v1 仕様

## 1. 目的

`your_singer` v1 は、ノイズを含む動画・音声素材群から対象話者を抽出し、既存ソフトで利用可能な **歌唱モデル** と **トークモデル** を生成するためのソフトウェアです。

v1 の主眼は、綺麗に収録された専用データセットを前提にせず、フォルダにまとめられた実在素材を入力として、解析・選別・品質診断・学習データ構築・モデル生成までを一貫して行うことです。

## 2. v1 の完成条件

最低限、次が一連で動作することを完成条件とします。

1. 単一ファイルまたはフォルダを読み込める
2. フォルダ配下の対応動画・音声を再帰的に列挙できる
3. 動画から音声を抽出できる
4. ノイズ・BGM・複数話者を含む素材を解析できる
5. 素材群全体を横断して話者をクラスタリングできる
6. 検出された話者を試聴し、学習対象を選択できる
7. 同一人物の分割クラスタを統合できる
8. 誤った区間を除外できる
9. speech / singing 区間を分類できる
10. 日本語50音・音素カバレッジを診断できる
11. 学習品質の注意を表示できる
12. 補完 / 補正をON/OFFできる。初期値はON
13. 歌唱モデルだけ、トークモデルだけ、両方、のいずれも生成できる
14. 初期対応する既存形式へ出力できる
15. 一度解析した素材の結果をキャッシュし、差分再解析できる

## 3. スコープ外

v1 では以下を必須としません。

- 独自の歌唱エディタ
- 独自のトークエディタ
- 独自モデル形式を本番運用するランタイム
- 声色を時系列スクリプトで制御する独自形式
- 入力元データの権利・ライセンス・許諾状態の自動判定や検証

既存ソフトで利用可能なモデルの生成を優先します。

## 4. 入力仕様

### 4.1 入力方法

- **フォルダ選択**を主導線とする
- **単一ファイル選択**もサポートする
- フォルダ入力では配下を再帰走査する
- 非対応ファイルは無視する
- 1フォルダを基本的に1素材ライブラリ / 1プロジェクトとして扱う

### 4.2 代表的な対応拡張子

動画:

- mp4
- mkv
- webm
- mov
- avi
- m4v

音声:

- wav
- flac
- mp3
- m4a
- ogg
- opus

実際にデコード可能な範囲は FFmpeg 等のバックエンド能力に依存させます。

### 4.3 差分読み込み

同じプロジェクトを再度開いた場合、ファイルごとに以下を記録し、変更・追加された素材だけ再解析できるようにします。

- path
- file size
- modified time
- content hash
- analysis version

解析器のバージョンが変わった場合は必要な段階だけ再計算できる構造を目指します。

## 5. 話者検出・選択

### 5.1 全体横断クラスタリング

話者クラスタリングはファイル単位で閉じず、プロジェクト内の素材全体を横断して行います。

同一話者が複数ファイルに登場した場合、それらを同じ話者候補としてまとめることを目指します。

### 5.2 話者選択UI

複数話者が見つかった場合、最低限以下を表示します。

- 話者ID / 仮名
- 使用可能と判断された音声時間
- 代表区間の試聴
- 選択状態

複数話者を同時に選択でき、それぞれ別モデルとして生成可能にします。

### 5.3 話者修正

以下を可能にします。

- 同一人物と判断した複数クラスタの統合
- 誤クラスタ区間の除外
- セグメント単位の採用 / 不採用変更

変更後は元メディアの重い解析をやり直さず、後段のデータセット構築から再実行できるようにします。

## 6. 歌唱 / トーク分類

抽出された各音声区間を少なくとも以下に分類します。

- speech
- singing
- unknown / ambiguous

歌唱モデル生成では singing を主に使用し、トークモデル生成では speech を主に使用します。

必要に応じて素材の一部を両方に利用できる余地は残します。

## 7. 品質診断

### 7.1 ユーザー向け50音表示

ユーザー向けには日本語の「50音がどの程度揃っているか」を分かりやすく表示します。

ただし内部評価は単純な文字存在チェックに限定せず、音素単位で行います。

### 7.2 内部評価対象

最低限、以下を考慮します。

- 母音
- 子音
- 濁音
- 半濁音
- 拗音
- 促音
- 撥音
- 長音
- 外来語系の拡張音素
- 各音素の出現回数
- 音素前後の文脈

歌唱用ではさらに以下を評価候補とします。

- 音域カバレッジ
- 高音域 / 低音域での各母音
- 母音伸長
- 子音→母音遷移
- ピッチ推定信頼度
- 長音の安定性

### 7.3 品質表示

不足があっても原則として学習を禁止しません。

例:

- 良好
- 注意
- 不足

不足音・弱い音・推定で補う必要がある音は一覧表示します。

## 8. 補完 / 補正

### 8.1 基本仕様

- ユーザーがON/OFFを選択可能
- **デフォルトON**
- 歌唱・トークの双方で利用可能な共通概念として扱う

### 8.2 ON時

ONは単なる欠損補完ではなく、より広い「自動補完・補正」モードです。

対象例:

- 欠損音素の推定
- 少量音素の補助
- ノイズ由来の外れ値抑制
- 不自然なセグメントの破棄
- 誤ラベル / 誤認識の補正
- 他音素からの特徴推定
- 他の音域・発声条件からの補間
- 音素間の声質整合
- 文脈差の一般化

十分な50音データが存在する場合でも、異なる音域・発声条件・文脈に対して補完が有効な場合があります。

また、外れ値を除去して話者の中心的特徴を推定するため、素材によっては **ONの方が元話者らしい結果になる可能性があります**。

### 8.3 OFF時

OFFでは推定による修正を最小限にし、観測された学習データを可能な限り優先します。

高品質で偏りの少ない十分な素材があり、収録された特徴を強く残したい場合に選択肢となります。

ON/OFFは「品質」と「忠実度」の単純なトレードオフとして説明しません。

## 9. 生成モデル

ユーザーは次から選択できます。

- 歌唱モデルのみ
- トークモデルのみ
- 歌唱モデル + トークモデル

複数話者選択時は話者ごとに同様の選択を適用できます。

## 10. 初期互換形式

### 10.1 歌唱

初期ターゲット候補:

- OpenUtau / DiffSinger 系

### 10.2 トーク

初期ターゲット候補:

- Style-Bert-VITS2 系

実装時には対象ソフトの現行仕様を確認し、互換範囲を別ドキュメントに固定します。

## 11. UIの基本フロー

```text
新規プロジェクト
  ↓
フォルダを選択 / ファイルを選択
  ↓
素材スキャン
  ↓
前処理・話者解析
  ↓
話者一覧 + 試聴
  ↓
対象話者を選択 / 必要なら統合・除外
  ↓
音素・50音・音域などの品質診断
  ↓
補完 / 補正 ON（既定） / OFF
  ↓
歌唱 / トーク / 両方 を選択
  ↓
学習
  ↓
既存互換形式へ出力
```

## 12. 設計原則

- 重い解析をできるだけ一度で済ませる
- 歌唱 / トークで共通化できる前処理は共有する
- 中間成果物を保持し、後段だけ再実行できるようにする
- Exporterを交換可能にする
- 将来の独自形式を追加しても前処理基盤を作り直さない
- 警告はユーザーの判断材料として出し、不必要に処理を禁止しない


## 13. 技術アーキテクチャ / 配布要件

v1 の技術構成は以下を基準とします。

- メインアプリケーション: C# / .NET / Avalonia
- MLバックエンド: Python / PyTorch
- 設計: UPD Commander Base Design + OOP
- AI開発支援: ai-context-reducer
- oop-design-checker は必須ではなく、任意のCI / レビュー補助として扱う

### 13.1 配布条件

- ユーザーに Python のインストールを要求しない
- ユーザーに .NET Runtime のインストールを要求しない
- 公開起動ポイントは原則として `YourSinger.exe` 1箇所とする
- 内部に複数の worker exe / DLL / runtime / native library を含むことは許容する
- Python worker はアプリに同梱し、メインアプリからのみ起動する

### 13.2 ML実行条件

- 学習・重い推論はローカルGPUを基本前提とする
- ハードウェアに応じて High Quality / Balanced / Lightweight 等の処理モデルを選べるようにする
- Auto モードでは GPU / VRAM / RAM 等から推奨プロファイルを選択する
- CPU-only は完全非対応とせず、可能な範囲で軽量構成を提供する

### 13.3 プロセス境界

C# 側は UI / Project / Job / Data / ML Worker Control を担当し、Python 側は音声解析・学習等のML処理を担当する。

大きな音声・tensor・model weights は IPC へ直接流さず、project workspace 上の artifact として保存し、IPC では path / id / metadata を受け渡す。

詳細な責務境界・IPC・worker配布方式は `docs/architecture.md` を正とする。
