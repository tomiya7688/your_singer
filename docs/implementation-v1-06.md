# v1-06 実装設計: 50音・音素カバレッジ診断と品質警告

## 対象Issue

- #7 v1-06: 50音・音素カバレッジ診断と品質警告を実装する

## 目的

Universal Voice Dataset に保存済みの音素情報を利用し、学習前に日本語の発音カバレッジと偏りを診断する。

## 診断単位

以下のscopeで個別に診断する。

- プロジェクト全体
- 話者単位
- 話者 × Speech
- 話者 × Singing

ambiguous は用途別診断には含めない。

## 内部評価

内部では音素単位で以下を集計する。

- 各音素の出現数
- 前後音素を含む文脈
- 日本語モーラ表示用の対応数
- 拗音
- 濁音
- 半濁音
- 促音 / 撥音 / 長音
- 外来語系拡張音

## 50音表示

UI向けには `BuildKanaView` で音素数を日本語かなへ投影する。

各かなは構成音素の最小出現数を採用する。
例えば「か」は k と a の少ない方をそのかなの実質カバレッジとして扱う。

## 判定

音素単位:

- 0件: 不足
- 1〜2件: 注意
- 3件以上: 良好

カテゴリ単位:

- 80%以上観測: 良好
- 50%以上: 注意
- 50%未満: 不足

scope全体は不足音素や少量音素、カテゴリ不足を加味して判定する。

## 警告の扱い

診断結果は学習をブロックしない。

不足・注意は品質警告として保持し、後続の補完・補正や学習対象選択の判断材料として使う。

## 前後文脈

各音素について以下の形式で文脈頻度を保持する。

```text
previous|current|next
```

これにより、単純な出現数だけでなく前後文脈の偏りを後続処理で評価できる。

## 保存

診断結果は以下へ保存する。

```text
metadata/phoneme-coverage.json
```

## UIとの境界

このIssueでは診断データと50音表示用viewまでを実装する。

実際の一覧・色分け・品質警告表示は #13 のUIで実装する。

UI文言は日本語で統一する。
