# モデル学習・データ活用設計（v1）

## 目的と完成基準

Your Singer は研究用の実験フレームワークではなく、さまざまな動画・音声素材を投入して実際に使用可能な歌唱モデル・トークモデルを生成するデスクトップアプリケーションである。

v1.0.0 の必須方針:

1. 有用な低品質素材を一律に破棄せず、信頼性・学習上の価値に応じて重みを付けて利用する。
2. **Fine-tuningのみの製品にはしない。** 事前学習モデルからの追加学習と、モデル初期化からの新規学習の双方を提供する。
3. ユーザーは入力前に素材を歌唱・トークへ仕分ける必要がない。システムが区間を分類し、適切な学習用途へ振り分ける。
4. 学習ジョブの完了と生成モデルの実用検証を区別する。実際の音声生成・出力形式の読み込み・音声品質を検査して完成判定する。

細かな閾値・モデル名・ハイパーパラメータは実装時に検証して固定する。

## 1. 有効性と品質を分けて判定する

各Segmentの評価は少なくとも次の独立概念を持つ。

- **使用適格性（eligibility）**: そもそも対象話者・目的のモデル学習に使用できるか。除外は明示的な理由付きで行う。
- **品質・信頼性（quality / confidence）**: 音響品質、文字起こし、音素、音素境界、F0等の推定がどれほど信頼できるか。
- **学習上の有用性（utility / coverage contribution）**: 希少音素、希少音域、発声様式、遷移等の新しい情報が含まれるか。

**低品質 ≠ 使用不可**。低SNR、軽度のBGM漏れ、残響、圧縮劣化があっても、有用な音素や発声情報が取得できる区間は、原則として学習候補として残す。

明示的な除外候補:

- 選択対象と異なる話者と十分な根拠をもって判定された区間
- 実質的な有声音声が存在しない区間
- 音声が破損・欠損し、復元・解析・学習への利用が困難な区間
- 重複・誤アラインメントなどにより対象学習タスクの正解データとして成立しない区間（利用可能な部分は分割して保持）
- ユーザーが明示的に除外した区間

**未計測・未校正・取得失敗のconfidenceは「低信頼と測定された」と同義ではない。** null / unknown と既知の低値を区別する。未計測を機械的な0点として扱って素材を捨てない。推定値を捏造して高信頼扱いもしない。

除外対象となった場合も元データ・理由・評価根拠を記録し、再解析やユーザー修正で復帰可能にする。

## 2. v1 の基本的な重み付き学習

- 使用適格な区間に対し、品質と学習上の価値に基づく **非負の学習weight** を計算する。
- 高品質で信頼性が高い区間を強く利用するが、低品質で有用な区間も **意味のある重み** を持たせる。
- 希少音素・希少音域などのカバレッジ寄与を考慮し、単に低品質という理由で貴重な区間が学習から消えないようにする。
- 対象モデルに無関係な情報だけを理由に重くしない。トーク用・歌唱用で適格性・品質・重みが異なる場合を認める。
- 無効データはweight 0または除外扱いとし、理由を記録する。
- 正常な低品質データに一律weight 0を付けて事実上破棄することはしない。
- 極端なweight偏重や同じ短いクリップの過学習を避けるため、weight範囲・正規化・重複処理・バランスを検証する。
- 重み付けはBackend Adapterを通してDataset Builder / Trainerへ反映する。使用モデルによりweighted sampling、per-sample loss weighting等の実現手段を選び、**二重適用で意図せずweightを増幅しない**。
- 使った重み・判断理由・計算version・モデル用途を保存し、再学習時に追跡できるようにする。
- 完成前に、重み付けなしの対照条件も含めて実際の生成品質で効果を検証する。

この **品質・有用性に基づく基本weightingはv1.0.0の必須要件**。v2.x予定のSource Profileを用いた高度なAdaptive Trainingとは区別する。

## 3. 学習経路

v1.0.0では、歌唱・トークのそれぞれについて少なくとも次の学習経路を実際に動作させる。

- **自動**: 学習素材・利用可能なモデル・ハードウェアを踏まえて初期化方法を選択する（推奨の初期UI選択）。
- **事前学習モデルから追加学習**: 既存checkpointの知識を利用して対象話者へFine-tuning / 継続学習する。
- **新規学習（最初から）**: 事前学習済みの声のcheckpointを前提とせず、対応Trainerのモデル重みを初期化してデータから学習する。

ただし「新規学習」は学習素材・GPU・所要計算・モデル構造によって品質や成立条件が大きく異なる。少量の雑多な素材で高品質を保証しない。学習可能条件を診断し、厳しい場合は警告し、利用可能な方法と推奨方法を説明する。

すべてのBackendがすべての方法に対応する必要はないが、**歌唱出力・トーク出力の各々について新規学習と追加学習の実用経路を少なくとも一つ確保する**。対応しない組合せを見かけ上成功としない。

学習方式と成果物互換形式は別概念とする。出力形式の互換性は実際に対象ソフトで読み込み・生成して検証する。

## 4. 素材仕分けは自動化する

単一の動画、フォルダ、話者混在、雑談・歌唱混在をそのまま入力できるようにする。

```text
任意の動画 / 音声フォルダ
  ↓
共通音声解析・話者識別
  ↓
Segmentごとの Speech / Singing / Ambiguous分類
  ↓
Universal Voice Dataset
  ├─→ Talk Dataset Builder → Talk Training
  └─→ Singing Dataset Builder → Singing Training
```

- ユーザーに事前に「トーク用素材フォルダ」と「歌唱用素材フォルダ」を分けさせない。
- 自動分類結果に応じて各用途のDataset Builderが使う区間を決定する。
- 発話区間の話者特徴を歌唱モデルの声質適応に、歌唱区間の発声特徴をトークモデルの補助学習に利用できる拡張点を備える。生データを無条件に異なるタスクの教師データとして流用せず、利用目的・信頼性・変換手法を区別する。
- ambiguousを単純に削除しない。タスクごとの適格性・confidenceを評価し、推定困難なら確認候補へ回す。
- 目的に応じて同一区間を双方へ利用可能とするが、安易に二重利用して品質を損なわないようにする。
- 分類・話者・歌詞などのユーザー修正は可能にするが、通常フローで手作業を必須にしない。
- 分類やweight変更では重い音声抽出からやり直さず、必要な後段のみを再実行する。

## 5. 実用を基準にした完成検証

学習中は進捗、エラー、素材採用数、除外理由、学習weightの分布をユーザーにわかる形で提示する。

学習後は以下を実施する。

- 実学習・checkpoint生成が完了し、結果ファイルが存在・読み込み可能であること
- トークでは学習に使用していない文章を使って実際に音声を生成できること
- 歌唱では学習に使用していない歌詞・音符で実際に歌唱レンダリングできること
- 可能な範囲で発音、話者類似度、ノイズ、音程、音声の破綻などを評価し、ユーザーに結果を示すこと
- 対応する既存形式のTargetアプリ／推論環境で読み込み・音声生成を検証すること
- 失敗・未検証・部分的成功を成功扱いしないこと
- 検証用データと学習用データの重複・同一素材からの漏洩を可能な限り防ぎ、結果を過大評価しないこと
- 複数checkpointの品質を比較できる場合は最良候補を選択し、選定理由と再現可能な設定を保存すること

単体テストやダミー入力成功だけで、一般ユーザー向け機能の完成と判定しない。実素材でのE2E検証を完了条件へ含める。

## 6. v2.xとの境界

v1 は **基本の区間別重み付け、自動素材分類、複数学習経路、実用的な品質検証** を必須とする。

v2.x の Adaptive Training は、Source Profileに応じてsampling ratio、augmentation、loss weighting、補完強度、学習方針等をさらに自動調整する高度化であり、v1の基本weightingを先送りする理由にはしない。
