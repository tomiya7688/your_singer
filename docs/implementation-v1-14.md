# v1-14 実装設計: 回帰テストとE2E検証の境界

## 対象

ビルド成功、データ境界テスト成功、実モデル学習成功、対象ソフトでの音声生成成功は別々の検証結果として扱う。

## 自動テストの範囲

| 区分 | 入力と検証範囲 | 検証しないもの |
| --- | --- | --- |
| .NET回帰 | 一時プロジェクト内の解析済みfixtureを使用。話者統合、区間除外・復帰、分類修正、学習ジョブ、両データ構築器、音素診断、保存、内容識別子 | MLの認識精度、実学習、実音声生成 |
| 入力走査 | 単一ファイル、再帰フォルダ、日本語パス、拡張子、内容ハッシュ、解析版による差分判定 | 動画の全コーデック対応 |
| 実FFmpeg統合 | 生成したPCM WAVを実FFmpegで読み込み、WAVとプロジェクト状態を保存。破損素材の継続処理、未変更音声の再利用 | ML前処理以降、人物の声・学習品質 |
| ワーカー通信 | 依存なしで起動するコマンド境界。JSON応答、要求ID、ログ分離、依存不足、不正要求、例外、非有限値 | 実モデルによる成功応答、C#側の長時間プロセス制御 |
| 出力境界 | 登録済み出力形式の解決、必須ファイル欠落の拒否 | 正常なモデル重みのロード・レンダリング |

fixtureはテスト専用の短い合成波形と明示的な解析結果である。人物の録音、ダミーONNX、ダミー重みを用いて実学習や互換性に合格したように扱わない。

## 回帰テストで修正する動作

手動編集は補正ON/OFFより優先する。保存済みの共通音声データを削除せず、学習用の読み取り結果へ話者・分類・除外を反映する。
データ構築器も同じ規則を使用するため、ジョブ計画と構築時の用途・話者が食い違わない。

話者の総時間・使用可能時間は前処理区間の実際の長さを合算する。区間数の割合で秒数を推測しない。
区間長が見つからない場合は解析ファイルを上書きせず、確認を要求する。

内容識別子は`sha256-v2:`形式とする。スキーマ・処理版、補正設定、区間ID、元データのキャッシュキー、文章、音素時刻、音高、韻律、話者特徴を含める。
区間はID順に並べ、数値はJSONで直列化する。絶対パス、保存日時、表示言語、列挙順は識別に使わない。
各ジョブでは話者・用途・選択区間も含める。ジョブ作成後の変更や旧識別形式を検出したら再計画を要求する。

トーク学習入力は`training/style-bert-vits2/<job-id>/dataset/`に作成し、一時ディレクトリで完成させてから置換する。
学習済み重み・ログのあるジョブのディレクトリ全体は置換しない。

## 実行方法

開発者の検証用コマンドであり、配布アプリの利用者にPython導入を要求するものではない。

```sh
dotnet test tests/YourSinger.Process.Tests/YourSinger.Process.Tests.csproj --configuration Release --filter "Category!=FfmpegIntegration"
python -m unittest discover -s tests/worker -v
```

実FFmpegテストは実行ファイルを明示する。未指定の場合はスキップされる。CIのLinuxジョブでは明示的にFFmpegを導入して3件を実行する。

```sh
YOURSINGER_TEST_FFMPEG=ffmpeg dotnet test tests/YourSinger.Process.Tests/YourSinger.Process.Tests.csproj --configuration Release --filter "Category=FfmpegIntegration"
```

PowerShellでは実行前に`$env:YOURSINGER_TEST_FFMPEG = 'C:\tools\ffmpeg\ffmpeg.exe'`のように設定する。

.NET回帰テストはWindows / Linuxの両方で実行する。Python通信テストは3.11の標準ライブラリだけで実行する。
失敗時もTRXをActionsの`regression-<os>`へ保存する。保持期間は14日。テスト用データはケースごとの一時ディレクトリへ作り、終了時に削除する。

## 未完了のE2Eと統合課題

実素材から前処理、実話者識別、音素時刻推定、両モデルの学習、出力、対象ソフトでの音声生成まで通す試験は未実施。
OpenUtauの歌詞＋ノートからの歌唱生成（#11）、Style-Bert-VITS2の任意文章読み上げ（#12）、GUIのみでの全工程（#13）は未合格のまま残す。

特に現時点の自動補正コードは低信頼区間の除外と推定・補正対象の記録を行うが、欠損音素の実データ生成やF0の実値補間を実施していない。
ON/OFFテストの成功を実補完の完成と解釈しない。これも実学習前の統合課題として扱う。

将来の実機試験では、利用可能な素材、モデル・ランタイムの版とハッシュ、学習設定、環境、ログ、生成音声、試聴結果を保存する。
必要な資産がない場合は未実施と記録し、固定の成功値や空の音声を返して合格にしない。
複数ファイル間の同一話者識別精度、生成品質、GPU/CPU差、長時間処理の中断復旧、配布物のみでの起動も別途検証する。
